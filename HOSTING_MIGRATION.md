# Sengandhal free hosting migration (development / demo only)

## Services
- Web backend: Render free web service
- PostgreSQL: Neon free project (do **not** use Render's 30-day free database)
- Images: Cloudinary free image storage

These providers have usage limits and may change their free terms. Render free
services sleep on inactivity; cold starts can take up to roughly a minute.
This deployment is NOT guaranteed forever and is not client-grade uptime.

## 1. Back up existing information
If the Railway database is still accessible, export its data before doing
anything else. Old Railway data does NOT move automatically. If Railway has
expired and the database is no longer accessible, the new Neon DB will be empty.

## 2. Create Neon database
1. Create a free PostgreSQL project at https://console.neon.tech
2. Copy the full PostgreSQL connection string including sslmode=require.
3. Keep it private. Never commit this connection string to GitHub.
4. Prefer a region close to Render Singapore when available.

## 3. Create Cloudinary account
1. Register at https://cloudinary.com/
2. In Cloudinary's API settings, obtain CLOUDINARY_URL, or construct it from
   your own cloud name and credentials (never post it publicly).
3. Keep this URL private. Images are stored remotely even when Render sleeps.
4. Existing photos on Railway's local filesystem do not migrate automatically.

## 4. Deploy to Render
1. Open https://dashboard.render.com/blueprints
2. Choose New Blueprint Instance and connect babukrishnan/Backend-repo.
3. Select branch feature/client-ready-marketplace and use render.yaml.
4. Choose the free instance plan. Do NOT create Render free PostgreSQL: it
   expires after 30 days. The blueprint creates only a web service.
5. At the environment variable prompt enter your Neon DATABASE_URL and
   Cloudinary CLOUDINARY_URL. DJANGO_SECRET_KEY is generated by Render.
6. Wait for build (requirements, collectstatic, migrations) and deploy.
7. Copy your new https://...onrender.com URL and visit it.
   The root path should display a backend success message.
8. Test /api/products/ (public GET) and signup/login with test accounts.

## 5. Point Expo app at Render
In Frontend-repo, branch feature/client-ready-marketplace:
- Create a .env (ignored by Git) containing:
  EXPO_PUBLIC_API_URL=https://YOUR-SERVICE.onrender.com
- Stop Metro and run npx.cmd expo start --go --clear.
- Expo embeds EXPO_PUBLIC_ variables in the app bundle, so a published build
  needs rebuilding after changing the URL. Do not store secrets in EXPO_PUBLIC_.

## 6. Safety and production warnings
- Previously committed secrets are still present in old git history after
  deletion. ROTATE the old database credentials and Django SECRET_KEY.
- Do not merge or deploy to real clients before testing signup, media uploads,
  purchases, permissions, migrations, backups, and compliance requirements.
- Use a proper paid service or uptime SLA for client production availability.
- Check provider usage limits and avoid surprise billing.
- Render free web service has ephemeral disk. Never store user uploads or
  production SQLite files on the Render local filesystem.
